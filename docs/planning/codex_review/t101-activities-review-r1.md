# Поведенческое ревью `activities` r1

## Результат

Новых поведенческих дефектов в изменённом коде не обнаружено. `activities`:

- маршрутизируется через `open_readonly`, не создаёт и не мигрирует БД;
- выбирает только `watch_sessions`, исключая `hr_json`, с `ORDER BY start DESC` и параметризованным `LIMIT`;
- преобразует RFC 3339 `start` в UTC, сохраняет `NULL` для отсутствующих HR/calories/type/name/source и сериализует `WatchActivity` в JSON;
- использует `activity_type`, а при его отсутствии — `name`, и печатает `-` для отсутствующих значений в human-форме;
- имеет allowlist `--json`, включающий `activities`, и корректно обрабатывает пустой дневник и отсутствующую БД.

Проверка согласованности `AGENTS.md`: строка таблицы команд и пример объекта соответствуют полям фактического JSON-контракта; `Z` вместо `+00:00` в фактической сериализации — допустимые варианты RFC 3339. Единственная неполнота документации — перечень read-команд в начале файла явно перечисляет `list`, `stats`, `tui`, но не `activities`; таблица команд ниже всё же классифицирует `activities` как `read`, а код соблюдает read-only поведение. Это не поведенческий дефект.

Проверка инвариантов r1–r9 не выявила регрессий: изменения activities используют существующую проверку полной схемы, не затрагивают pulse-миграции, source-фильтр, идемпотентный upsert/sync, выбор владельца, независимое заполнение pulse, выбор содержащей сессии и existing-only открытие.
