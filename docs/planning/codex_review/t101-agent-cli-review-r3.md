# Ревью T-101, раунд r3

## Итог

Патч пока нельзя считать корректным: проверка `--create` учитывает только отсутствие пути, поэтому уже существующий пустой или посторонний SQLite-файл команды записи инициализируют без разрешающего флага. Исправления product-кода по findings r1/r2 подтверждаются статически; отдельно остаётся недетерминированным новый negative control для cross-user мутанта.

## Findings

### [P1] Не инициализировать существующий пустой файл без `--create`

`src/main.rs:173-179`: при `may_create == false` проверяется только `Path::exists()`, после чего `Database::open()` безусловно выполняет `init_schema()`. Поэтому точная репродукция `touch empty.db; majowuji --db empty.db log jab` успешно создаёт схему и запись без `--create`; аналогично существующий посторонний SQLite-файл получает таблицы majowuji. Это обходит явный контракт, по которому `log` и `intervals sync` могут инициализировать БД только с `--create` ([AGENTS.md:32-34](/home/ryazanov/Development/fitness/majowuji/AGENTS.md#L32-L34)). Для пути без `--create` нужно валидировать существующую majowuji-БД, а не вызывать create-or-migrate open.

### [P3] Сделать cross-user negative control детерминированным

`tests/cli.rs:422-425`: дата чужой строки вычисляется через `strftime(..., 'now')` после отдельного процесса `log`. Если вставка попадает уже в следующую секунду, CLI-строка имеет offset около 60, чужая — около 61, а в HR-фикстуре между offset 40 и 70 нет сэмпла; без фильтра `user_id.is_none()` первая строка получает link, но для чужой `hr_max(60, 61)` возвращает `None`, и мутант может пройти все текущие asserts. Исторический красный прогон мутанта мог попасть в ту же секунду (тогда усечённая дата чужой строки сортируется первой), но harness не гарантирует это; дату чужой строки следует задавать относительно фиксированного `start` так, чтобы она всегда получила link в мутанте.

## Перепроверка findings r2

1. **Cross-user связывание — product-дефект исправлен.** `src/main.rs:306-312` передаёт в `link_pulses` только строки с `user_id IS NULL`; это соответствует заданному для r3 определению CLI-записи и Known limitation в `AGENTS.md:98-103`. Строки, ранее присвоенные владельцу при первой регистрации, теперь намеренно не входят в этот контракт. Обычный тест проверяет, что строка с `user_id IS NOT NULL` остаётся пустой, но его mutant sensitivity имеет P3 выше.
2. **Release API-base override — исправлен.** `src/intervals.rs:173-177` читает `MAJOWUJI_INTERVALS_API_BASE` только при `debug_assertions`; стандартная release-сборка из `AGENTS.md` использует константу `API_BASE`. Debug/integration путь mock-сервера сохранён.
3. **Префикс source — исправлен.** `is_watch_source` использует точное `eq_ignore_ascii_case`, а `sessions_skip_close_prefix_sources` отбрасывает `ZEPPELIN` до запроса streams.
4. **Времязависимый peak — исправлен.** Последний сэмпл теперь также равен 100, поэтому обычный тест больше не меняет ожидаемый `pulse_after` при переходе времени log через offset 70. Это не устраняет отдельную временную зависимость mutant control, описанную выше.
