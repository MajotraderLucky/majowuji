## Проверка `activities`

Новых дефектов исполнения в `src/db/mod.rs` и `src/main.rs` не найдено:

- запрос читает только `watch_sessions`, не выбирает `hr_json`, применяет `ORDER BY start DESC LIMIT ?1`;
- `start` строго разбирается как RFC 3339, переводится в `Utc` и сериализуется `chrono` как RFC 3339 UTC;
- nullable-поля сохраняются как `Option`/JSON `null`, а human-форма печатает `-`; при `activity_type = NULL` используется `name`;
- `Activities` не входит в `writes_db`, поэтому проходит через проверку существования пути и `Database::open_readonly` без создания или миграции;
- global `--json` разрешён для этой ветки, default limit равен 10, явный limit передаётся параметром SQL;
- logged trainings в запрос не входят, поток HR в объекте `WatchActivity` отсутствует.

Четыре CLI-теста проверяют порядок и явный limit, поля/NULL и отсутствие HR-потока, fallback имени, пустой результат, отсутствующий файл и побайтовую неизменность основной БД. Отдельно они не фиксируют default limit 10, отображение каждого `NULL` как `-`, отказ на пустой/не-SQLite/устаревшей БД и ошибку повреждённого `start`; по статической трассировке эти варианты реализованы общими clap/schema/read-only путями, фактического дефекта в них не найдено.
