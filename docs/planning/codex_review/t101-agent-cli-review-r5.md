1. **r1 P2, частичная pulse-миграция — подтверждаю закрытие.** `src/db/mod.rs:194–203` отдельно проверяет оба столбца, а не проглатывает ошибку `ALTER`; `migrate_completes_partially_pulsed_database` проверяет сохранность имеющегося значения и добавление недостающего столбца.
2. **r1 P2, нерелевантные источники — подтверждаю закрытие.** `src/intervals.rs:146–152, 213–221` требует точного case-insensitive `ZEPP` до streams-запроса. Есть тесты для другого источника и близкого префикса.
3. **r1 P3, CLI-идемпотентность — подтверждаю покрытие в дереве, исполнение теста не подтверждал.** `tests/cli.rs` содержит `intervals_sync_cli_is_idempotent_and_fills_once`, который проходит через CLI дважды с mock API.
4. **r1 P3, пустое имя на отсутствующей БД — подтверждаю закрытие сценария неправильного порядка проверок.** Пустое имя проверяется после открытия БД (`src/main.rs:204–208`); тест сначала создаёт валидную БД и проверяет ошибку имени.
5. **r2 P1, связывание пульса между пользователями — подтверждаю закрытие.** Перед `link_pulses` записи ограничиваются `user_id.is_none()` (`src/main.rs:305–313`); интеграционный тест добавляет чужую запись внутрь временного окна и проверяет неизменность пульса.
6. **r2 P1, API-base override в release — подтверждаю закрытие по текущему исходнику.** Переменная окружения читается только под `#[cfg(debug_assertions)]`, а release использует константу `API_BASE` (`src/intervals.rs:170–177`). Фактическое поведение собранного release-бинарника не проверялось.
7. **r2 P2, префикс ZEPP — подтверждаю закрытие.** Сравнение использует равенство без учёта регистра, а не prefix match (`src/intervals.rs:148–152`); для `ZEPPELIN` есть тест.
8. **r2 P3, peak в CLI-тесте — подтверждаю заявленную детерминированность текущего теста.** В mock stream последний sample имеет значение 100, а assertion ожидает pulse_after 100 (`tests/cli.rs`, `intervals_sync_cli_is_idempotent_and_fills_once`).
9. **r3 P1, инициализация существующего пустого/чужого файла без `--create` — подтверждаю закрытие.** Путь без флага идёт через `open_existing`, требующий таблицу `trainings` и актуальную схему; миграция использует отдельный existing-only путь (`src/main.rs:165–190`, `src/db/mod.rs:68–93`). Тесты проверяют пустой и посторонний SQLite-файл.
10. **r3 P3, cross-user контроль — подтверждаю закрытие по текущему тесту.** Дата чужой записи задаётся относительно `start_dt` как `+45s`, а не от независимого wall clock (`tests/cli.rs`, тот же интеграционный тест).
11. **r4 P2, SQLite CREATE при открытии существующего файла — подтверждаю закрытие.** `open_existing` открывает через `SQLITE_OPEN_READ_WRITE | SQLITE_OPEN_NO_MUTEX`, без `SQLITE_OPEN_CREATE` (`src/db/mod.rs:68–72`); unit-тест проверяет отсутствие файла после вызова на отсутствующем пути.

## Проверка заявленного контракта

- Валидация пустого пути, `:memory:` и `file:`-префикса выполняется до открытия БД (`src/main.rs:141–144`).
- Чтение использует `SQLITE_OPEN_READ_ONLY`, проверяет наличие таблицы и актуальность схемы без запуска миграции (`src/db/mod.rs:110–129`); для записи без `--create` используется открытие существующего файла без SQLite CREATE-флага.
- `migrate` отсекает отсутствующий/пустой путь, затем открывает existing-only и вызывает миграцию (`src/main.rs:150–155, 181–189`; `src/db/mod.rs:84–92`).
- Командный продукт печатается через stdout, tracing направлен в stderr (`src/main.rs:127–137`); ошибки передаются через `anyhow`/clap, а CLI-тесты проверяют пустой stdout при runtime-ошибке.
- Sync делает upsert по ID, pulse update сохраняет уже положительные значения отдельно по полям, а нулевые HR-сэмплы отбрасываются (`src/db/mod.rs:239–257, 262–283`; `src/intervals.rs:250–261`).
- API-base override ограничен debug-сборками (`src/intervals.rs:170–177`).

Статусы прошлых находок подтверждены только по доступному текущему исходнику и тестам; исторические результаты выполнения тестов, мутационные прогоны и свойства конкретного release-артефакта независимо не воспроизводились.
