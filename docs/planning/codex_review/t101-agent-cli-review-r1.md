# Ревью T-101, раунд r1

Проверена дельта `bf587c8..f1a9845` в рабочем дереве. Выполнены `cargo test -j 2 --test cli` (18/18) и библиотечные тесты (158/158). Сетевой API вживую не проверялся; HTTP-поведение проверено локальным mock-сервером из `src/intervals.rs`.

## Findings

### [P2] Исправить миграцию частично существующих pulse-колонок

`src/db/mod.rs:146-158`: миграция считает pulse-схему готовой, если существует только `pulse_before`, и в этом случае не добавляет отсутствующий `pulse_after`. Такой файл может остаться после прерывания предыдущей миграции; `migrate` затем не обновляет его и завершается ошибкой проверки схемы, хотя контракт обещает обновлять устаревшую существующую БД (`AGENTS.md:30-31`). Проверять и добавлять каждую колонку отдельно, не игнорируя результат `ALTER TABLE`.

### [P2] Отфильтровать не-watch активности перед связыванием пульса

`src/intervals.rs:191-208`: `sessions()` превращает каждую активность из общего `/activities` ответа в `WatchSession`, не используя `source`/тип для отбора. Если в диапазоне есть импортированная из другого источника или ручная активность с HR, она сохраняется и может первой связать тот же logged training с чужим пульсом; после этого поля считаются заполненными и следующий sync их не заменит. Это нарушает контракт импорта watch workouts и заполнения пульса только по соответствующей watch-сессии (`AGENTS.md:86-91`).

### [P3] Запустить второй sync в интеграционном тесте

`src/intervals.rs:397-410`: mock-тест вызывает только `Client::sessions()` один раз, затем напрямую вызывает `link_pulses`/`fill_training_pulse`; он не вызывает CLI `intervals sync`, `upsert_watch_session` и второй sync. Поэтому заявленная идемпотентность `watch_sessions`, повторный вывод и фактический путь через `INTERVALS_API_KEY` этим тестом не подтверждаются (`AGENTS.md:86-91`).

### [P3] Исправить false-positive проверку пустого имени

`tests/cli.rs:139`: случай с упражнением из пробелов запускается на отсутствующем `t.db` без `--create`, поэтому команда завершается на проверке отсутствующей БД (`src/main.rs:173-177`) и до проверки `exercise.trim().is_empty()` (`src/main.rs:193-196`) не доходит. Negative control не подтверждает заявленную ошибку пустого имени; сначала нужно создать валидную БД.

## Проверенные утверждения и ограничения

- Read-only открытие, отсутствие создания/изменения БД, ошибки для text-файла, каталога, пустого файла, `:memory:` и `file:` URI подтверждены тестами и кодом.
- `list`, `stats`, JSON-формы, границы `sets`/`reps`/duration/pulse и миграция обычной старой схемы подтверждены тестами.
- Код сохраняет положительные pulse-значения и трактует `0` как пропуск; библиотечные тесты это подтверждают.
- В `tests/cli.rs` нет mock API и нет второго CLI sync; mock находится только в unit-тесте `src/intervals.rs`, поэтому утверждение о полноценном idempotent sync negative control не подтверждено.
- Комментарий о наблюдении `01.10` (warmup) является заявлением из diff и локальными фикстурами, но не независимым наблюдением.
